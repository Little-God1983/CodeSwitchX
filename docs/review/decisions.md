# Review decisions

Read by every layer review (see `review-prompt.md`). "By design" items are settled and
are not findings. When a review rules something as by design, it is added here in that
layer's PR, with the issue number.

## By design

### Deviations from the original design document

The deviations table at the top of `docs/superpowers/specs/2026-09-23-codeswitchx-design.md`
is settled: WPF instead of WinUI 3, project and file names, `csx-hook.exe`, the
`%LOCALAPPDATA%\CodeSwitchX` data folder, H.NotifyIcon.Wpf, hook entries recognised by the
`csx-hook` marker in the command, named pipe plus 127.0.0.1 transport behind one token,
Ctrl+Shift+Alt+1..9 jump hotkeys, `summary` lines as chat titles (current Claude Code writes
its generated title as `ai-title` lines instead, which count the same, L5 #8), and `SessionStart` with
`source: compact` leaving the state alone.

A pragma that fails closes the connection it was run on (#31) | EF Core 10 sends one parameter per item by default and SQLite takes 32,766 per statement. `synchronous` is per connection, so set once it reached only the pooled connection that ran the initializer. NORMAL is safe in WAL mode only; in rollback-journal mode a power loss can corrupt the database. Microsoft.Data.Sqlite pools the physical connections with their pragmas and hands them to any connection object, so the mark is on the handle, not the object, and a fresh handle for a marked object still gets the pragma. EF Core records an open only after the interceptor returns, so an open connection left behind by a failed pragma would never be closed or configured |

Only the latest value of a key matters, so changes behind a running save collapse; a write waiting out SQLite's busy timeout must not hold every later key back; a change made right before the exit must be in the database at the next start. | Persistence | The newest 20,000 seen message ids are kept, pruned on the hourly cycle | `--resume` dedup across restarts at bounded size |

| Ingest | A transcript pass moves the chat's inferred state only when it has lines with a timestamp and reaches the end of the file; an interrupt in a pass cut short is reported with the pass that reaches the end. | Ingest | A transcript whose stored offset no longer follows a line end, or that shrank below it, was rewritten: it is read again from the start without sending its title again, and usage stamped at or before the newest usage already counted from it is not counted again. After a restart, until the file counts new usage, the bound is the last write indexed before it (L5 #8) | Claude Code cuts a retracted message out of the file and writes back what followed. The message id memory keeps only the newest 20,000 ids, so after a long history it no longer knows which of a chat's earlier messages were counted. Assistant lines are stamped when their message starts, so they can be older than the line above them but are in order among themselves; the file's write time would cover lines not read yet |
| Ingest | A chat's title follows Claude Code's own order: a `/rename` name (`custom-title`), then the generated title (`ai-title`, `summary`), then the first prompt; a later `/rename` replaces an earlier one, a later generated title or prompt replaces nothing above it. A rename in CodeSwitchX (`SessionEngine.Rename`, which locks the title) wins over all three. The title and its source travel with the transcript cursor, and a restart sends the stored title again with the file's first live update (#28) | Claude Code's session list shows the `/rename` name first. Claude Code re-appends its `ai-title` line as the transcript grows, so the first generated title must keep winning over its copies. The chat engine drops a historical update of a chat it does not show, title and all, so a title found while the chat was historical has to survive a restart somewhere; the cursor is the row that outlives the chat |
| Ingest | A scan takes each file's size and write time from the enumeration and asks the file system again for files written within the history window (24 h), for every file once a minute (the watcher refresh) and on every scan without a watcher. A scan forgets the transcripts it no longer finds, in memory and, through the writer (`TranscriptsForgotten`, in order with the cursors still queued), in `TranscriptCursors`, after listing each missing file's folder; a folder it cannot list keeps its cursors, and a file found in place outside the enumeration is looked for again once a minute (#28) | Windows reports a write through a handle still open only once it reaches the disk, to the folder entry and to the watcher alike, so neither can be waited for; the minute refresh bounds the delay as the second stat per file did, which cost 118 ms of a 125 ms scan over 2560 transcripts, with a scan every 2 s while any chat writes. Claude Code's `cleanupPeriodDays` deletes old transcripts, and every start loaded every cursor ever stored. The enumeration skips a folder it cannot open (`IgnoreInaccessible`), and `File.Exists` says false there too; forgetting those files would read them from the start, and count their usage again, when the folder opens again. A row removed by the indexer itself could be written back by a cursor still queued in the writer |

| Sessions | A chat waits for a set of agents: a `PermissionRequest` adds the agent it names (none: the main agent); a Notification adds the agent it names, or for a nameless `permission_prompt` the agent of the latest tool use still open unless a prompt already waits, and for any other nameless dialog the main agent.
